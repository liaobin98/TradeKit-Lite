# 开发指南

本文是当前业务规则、代码结构、字段输出和维护约定的唯一开发基线。使用方法见 [README](../README.md#使用说明)，验证证据见 [TESTING.md](TESTING.md)，部署与凭证配置见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 1. 业务范围与规则

- 六类单据共用买卖方、银行、贸易条款和产品表；PI 追加运费，CD 追加六个行字段和十八个整单字段。SC 暂无专属合同/签章模块，CI 暂无专属运输模块，PL 仍为带价格的公共产品表。
- 每类支持多份独立 ID 单据及草稿，编号不是存储主键；编号/日期自动生成，尚无独立编辑入口。每份只保留一份轮换的上次版本，不提供完整历史。
- 新建空白仅创建独立编辑入口，填写内容或明确保存后才入库；清空卖方、银行信息及 Logo，保留样式、语言和默认条款。首页仅有对应已提交草稿时提示恢复或新建，多份草稿取最近修改的一份；新建不删除原记录。
- 列表按 ID 打开、选择和删除，类型筛选/数量只统计实际记录。行点击与选择/删除控件独立；全选限当前分类，切换分类清空选择。删除须确认，取消/Escape 不写入；任何所选原文已变化，整批拒绝删除，不影响独立目录、未选单据和下载文件。
- 十款模板、十种主题、三种语言；用户内容不自动翻译，中英文产品名称均保留。单张图片最多 2,000,000 字节，Logo 支持裁剪、更换、删除；无 Logo 时屏幕预览保留占位，打印/PDF 隐藏。
- 工具包括四个城市时钟（九个选项）、四种对 CNY 的参考汇率（26 个选项）、本地规则解析及可选在线 AI。汇率日期使用上游日期，缺失时不伪造；AI 须用户同意发送原文并确认候选。
- 不提供账号、云同步、多人协作、类型转换或海关申报；保存/输出不是交易或合规证明。真实供应商、平台、移动和完整无障碍验收见测试文档。

## 2. 项目目录与职责

```text
src/                         浏览器应用与按功能就近维护的单元测试
  main.tsx                   资料初始化、加载/恢复状态与应用挂载
  app/                       App 页面编排、首页、导航、移动菜单和项目链接
  features/
    documents/               单据模型、编辑/预览、工具栏、列表、保存、校验和输出
    catalogs/                买方、卖方、产品资料库及身份/收录/迁移/检索
    workspace/               IndexedDB、资料事务、设置保存和备份恢复
    rates/                   汇率模型、查询状态与展示
    world-clock/             城市配置、时区计算和定时更新
  components/                跨功能控件、状态提示与列表通用样式
    ui/                      基础 UI 控件及原始许可
  lib/                       通用请求与工具函数
  styles/                    主题、全局布局、参考布局和打印样式
tests/
  integration/               跨功能的语言、输出、批量删除和控件验证
  config/                    Vite 配置验证
cloud-functions/             共享 API 及 EdgeOne Node 入口
cloudflare/                  单个 Worker 入口与运行时 API 适配
wrangler.jsonc               唯一 Cloudflare 配置，内置 dist/ 静态资源
server/ / server.mjs         Express 生产/本地适配与启动
public/                      静态资源、生成的许可声明
site/                        公开使用说明与机器可读模板；域名在构建时配置
scripts/                     持续回归、站点构建、许可收集及发布工具
docs/                        需求、使用、开发、部署及验证说明
dist/                        构建输出，不是产品源码
test-artifacts/              验证产物，不是业务资料归档
```

`node_modules/`、`dist/`、`test-artifacts/`、`.wrangler/`、真实 `.env` / `.dev.vars` 均不作为提交源码；npm/pnpm 锁文件同步包含固定版本 Wrangler，标准运行命令以 `package.json` 的 npm scripts 为准。

新增功能优先放到对应 `features/` 目录，组件、业务逻辑、专属 CSS 与单元测试就近维护；只有跨功能复用的代码进入 `components/` 或 `lib/`。应用源码使用已配置的 `@/` 别名，跨功能测试使用相对路径。`model.ts` 不引用存储或草稿模块，避免基础模型反向依赖保存流程。单据和资料库共享的列表样式放在 `components/library.css`。

`index.html` 内置加载内容和关键样式，脚本下载前即可显示；`StartupLoading` 使用同一组样式，覆盖资料初始化，成功后进入应用、失败后进入恢复页。产品介绍放在 `noscript`，不再作为加载占位。全局样式由 `main.tsx` 按既有顺序加载，保留层叠关系；功能列表、弹窗等样式跟随组件引用。Tailwind 的 `@source` 覆盖整个 `src`，迁移文件时须同步检查扫描范围、`components.json`、读取源码的测试和浏览器验证脚本中的导入路径。

## 3. 数据与事务边界

### 当前存储

- 数据库：`tradekit-lite-workspace`，IndexedDB 结构版本 1，object stores 为 `values`、`images`、`meta`。
- 业务键前缀保持 `trade-toolbox:v1:`。单据数据 `Doc.version` 为 1；目录 `CatalogStore.version` 当前为 3，兼容旧 1/2。这些版本号分别表示不同结构，不能混为同一升级号。
- `workspaceStorage()` 提供已提交的同步只读快照；数据变更必须经 `updateWorkspace(storage => ...)`。事务内读取最新数据、比较预期原文、写入记录及图片；提交成功后更新快照。
- 图片按相同数据共享引用，清理仅针对事务结束后不再被任何记录引用的图片；目录/历史仍引用时不能随来源删除。
- 通过 BroadcastChannel 刷新其他页面快照并触发冲突提示。禁止 `clear()` 和直接绕过事务写业务存储。
- 有变更的事务提交后另发本页 `workspace-committed`，供单据列表刷新；它与编辑器跨标签冲突事件分离，避免自己的成功提交被误判冲突。列表挂载也重读持久化快照；首页恢复和列表共用 `documentRecords()`。

### 初始化与兼容

启动先打开数据库并迁移旧 localStorage，提交失败保留原文；提交成功且旧值完全一致后才释放旧副本。首次初始化 `documents` 时按已确认规则清除旧 `draft:` / `draft-previous:` / `draft-corrupt:` 单据键，保留独立目录和设置；不重复重置，集合损坏时拒绝覆盖。用户升级注意事项见 [部署说明](DEPLOYMENT.md#7-浏览器资料与升级)。

### 草稿与目录

- `documents` 集合以独立 UUID 为键，保存原文、上一份原文和更新时间。`useDraft` 的保存队列、generation 和每记录预期原文共同阻止过时任务/跨标签覆盖；同类型其他单据可独立更新。每份单据只轮换一份上次版本。
- 卖方/买方分别按去除首尾空白后的公司名去重，不猜测大小写或别名。成功保存更新整份快照，清空值和 Logo 也覆盖旧值；常规读取或收集历史不得回退最新资料，无公司名不猜测合并。
- V3 产品须有中文或英文名称及 SKU，按去除首尾空白后的 SKU 精确匹配。“保存”“保存草稿”/成功输出可收录并更新完整快照；自动保存、历史读取和来源删除不收录中间版本。既有重复副本不擅自清除。来源带单据 ID，不能仅凭类型/编号打开另一份记录。
- 目录支持搜索及当前结果全选。删除目录写入身份删除标记，仅删除副本，不级联来源，读取或再次保存不能默默重建；目录识别 ID 经专用身份函数处理，不应在 UI 或备份中重新拼接另一套规则。
- 统一 JSON 备份保存全部单据 ID、状态、图片、恢复版本、独立目录/删除标记及常用设置，上限 50,000,000 字节；单份格式上限 20,000,000 字节。完整恢复替换全部业务键，单份导入新增记录，不动汇率/时钟/口令或其他应用。
- 恢复先预览范围、下载当前安全备份并确认，再由外层 IndexedDB 事务写入。非法文件或确认期间资料变化时拒绝恢复；跨标签冲突不提供强制覆盖。
- 顶部完整备份先尝试保存；失败时保留最近可读取的工作区快照，并将当前编辑加入 v2 备份的 `editing`。恢复时给副本新 ID，不覆盖已保存版本；旧 v1 完整/单份备份仍兼容。弹窗提供不依赖保存的“导出当前编辑副本”和确认后的“重新读取已保存版本”。恢复前安全备份也包含当前编辑；恢复确认仍比较持久化快照，拒绝期间其他标签的写入。
- 单据读取按记录隔离损坏内容，正常单据可继续读写；上一版本独立验证。恢复上一版本前，将完整损坏记录存入 `documents.quarantine` 原文数组并进行并发比较。整个容器无法解析时不重置，启动错误页提供原文备份和正常备份恢复。

## 4. 用户控制状态与输出集成

`Doc.status` 使用 `draft` / `saved`，界面只显示“草稿”，全部单据可直接编辑：

| 操作 | 规则 |
| --- | --- |
| 新记录自动保存 | 未填新空白不保存；填写内容后为草稿，约 700ms 防抖 |
| “保存” | 无必填、完整性或数值校验，成功后设为 saved、移除标签 |
| “保存草稿” | 成功后主动设为 draft |
| 编辑、自动保存、打开/离开、输出 | 更新同一 ID，不改变原状态、不锁定 |
| 保存失败或冲突 | 旧记录和状态不变，页面修改保留 |

旧 `PendingIssue` / `issued` 帮助函数只用于旧格式兼容测试，不参与编辑流程。

`validateDoc` 检查数值，`assertExportable` 仅用于导出/打印，不阻止普通保存。首页只查询对应类型最近修改的已提交草稿。hash 路由显示经 URI 编码的单据编号，内部导航/历史和存储仍以 ID 定位；重复/空编号附加 `?record=ID`，不猜测同编号副本，不兼容旧 UUID 路径。编号变化原位替换当前历史条目，刷新/返回不能换成同类型另一份记录。

新建先保存当前有内容的编辑，再打开未入库的新空白，不替换原件。`hasDocumentContent()` 排除本次新建时生成的编号/日期、继承的贸易默认值、默认单位/件数、空行和展示样式；用户修改这些业务默认值、填任一业务字段/产品值或上传图片即可自动保存。只跳过尚未入库的新空白；已有记录清空必须保存，手动保存及输出不受此自动保存门槛限制。

`beforeunload`、隐藏和 `pagehide` 尽力保存有内容的当前记录，未入库的新空白不写入、不弹未保存警告；不能承诺浏览器终止时完成。

输出库按需加载。XLSX 使用字段映射和静态金额，不随预览模板重排；预览/打印/PDF 共用内容。PDF 在独立的 1280px 排版环境中按 720px 纸宽分页，产品行不切断，续页重复标题和表头、添加页码，长备注可分段续页。图片/字体就绪后测量，图像按固定纸宽输出；单个超高产品或不可拆说明明确报错，不缩成难以阅读的整页。PDF 仍为栅格图、不可搜索文字；打印使用浏览器分页，真实输出仍须人工核对。

## 5. 字段输出与数值

当前编辑字段均保存在 JSON，打印取同一预览。额外旧属性兼容保留，但不重新启用为编辑/输出字段。

| 字段组 | 类型 | 预览 / PDF | XLSX |
| --- | --- | --- | --- |
| 编号、日期 | 全部 | 标题 | 整单资料 |
| 卖方公司、联系人、地址、电话、邮箱、官网、税号 | 全部 | 抬头/卖方区，已填内容全部展示 | 整单资料 |
| 银行名、账号、SWIFT | 全部 | 银行区 | 整单资料 |
| 买方公司、联系人、地址、电话、邮箱、国家/地区 | 全部 | 买方区，已填内容全部展示 | 整单资料 |
| 币种、贸易条款、付款方式、交期 | 全部 | 金额/条款 | 整单资料 |
| 产品中英文名称、编码、规格、数量、单位、单价 | 全部 | 产品表；名称不随语言隐藏，单价保留有效精度 | 独立列，中英文分别输出 |
| 产品图片、Logo | 全部 | 产品表/抬头 | 嵌入图片，WebP 转 PNG |
| 行金额、合计 | 全部 | 重算后显示 | 静态值，非公式 |
| 运费、小计、最终金额 | PI | 费用/合计，金额重算 | 整单资料及合计区 |
| HS 编码、原产国、包装、净重、毛重、体积 | CD 行级 | 产品信息逐项展示 | 六个独立列 |
| CD 整单字段（下列十八项） | CD | 报关区逐项展示，保留换行 | 整单资料 |
| 补充说明 | 全部 | 备注 | Notes 行 |
| 模板、主题、语言 | 全部 | 控制样式/系统标签 | 不重排样式 |

CD 整单十八项：申报日期、监管方式、出口口岸、目的国、目的港、运输方式、船名/航班、航次、提单号、原产国、贸易国、总件数、包装类型、总净重、总毛重、总体积、唛头、报关备注。单据 ID、状态、目录删除标记及旧折扣/签章/申报要素等额外属性不作为当前输出列或参与合计。

- Decimal.js 计算，按舍入后的行金额汇总。空数量/单价保留空白，未填完整的行不计入合计；合法零为零，非法值显示错误和“—”，不得默认为零。
- 数量/单价/PI 运费为非负十进制，最多六位小数、上限 10¹²；行金额上限 10¹⁵，数值文本最多 64 字符，不支持千位分隔符或科学计数法。
- 总件数为非负整数；重量允许 kg/g/t/lb/oz（无单位按 kg），净毛重统一换算 kg 后比较；体积允许 CBM/m³。不自动推断总重量/体积。

## 6. 控件规范

- 共享控件放在 `components/`，基础 UI 在 `components/ui/`，保留原始许可证。固定选项用 Radix Select，可输入下拉用 cmdk + Radix Popover，数值用 `NumericInput`。
- 输入样式由 `control-styles.ts` 与 `form-controls.css` 统一；业务 CSS 管理布局，不另设一套输入视觉。普通图标和间距调整无需永久像素测试。
- 768px 及以下使用移动菜单，集中放导航、备份与项目链接；选择页面、Escape 或外部点击后关闭。备份共享一个弹窗，关闭后焦点返回可见入口，切回桌面时关闭菜单。
- 可输入下拉选择选项、“使用……”或 Enter 后写入，支持自定义值及清空；键盘选择和焦点由 cmdk / Radix 管理。数值错误关联到输入，允许保存但禁止输出。
- 产品行有至少两项实际填写内容才确认删除，图片及默认单位/箱数不计入；单据和目录的删除/恢复始终需要确认。

## 8. 维护约定

1. 功能完成后同步本文业务规则/字段矩阵、README 使用说明及 TESTING 执行证据，清除矛盾旧表述。README 只写当前状态，变更历史放 CHANGELOG/发布说明。
2. 不用删除数据或改 origin 掩盖冲突，不回退独立目录到来源派生视图，不绕过 IndexedDB 提交提示成功。
